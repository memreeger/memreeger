## Flagship Build

<div align="center">

### Supplog

**Supplement, Medicine & Reminder Tracking Platform**

<img src="https://img.shields.io/badge/STATUS-ACTIVE_DEVELOPMENT-D97706?style=flat-square" alt="Active Development" />
<img src="https://img.shields.io/badge/FOCUS-BACKEND_FIRST-111111?style=flat-square" alt="Backend First" />
<img src="https://img.shields.io/badge/TYPE-FULL_STACK-7C2D12?style=flat-square" alt="Full Stack" />

</div>

<br/>

Supplog is designed to help users manage supplements, medicines, vitamins and personal routines through a secure, structured and user-owned system.

<table>
  <tr>
    <td width="33%" valign="top">
      <strong>Purpose</strong>
      <br/><br/>
      Replace fragmented tracking methods with a centralized platform built around personal routines and recurring records.
    </td>
    <td width="33%" valign="top">
      <strong>Engineering Approach</strong>
      <br/><br/>
      Separate responsibilities across controller, service and repository layers while keeping request and response contracts explicit.
    </td>
    <td width="33%" valign="top">
      <strong>Primary Focus</strong>
      <br/><br/>
      Authentication, authorization, resource ownership, predictable error handling and maintainable domain modelling.
    </td>
  </tr>
</table>

### Implemented Engineering Capabilities

* JWT-based authentication with Spring Security
* Role-based authorization for user and administrative operations
* DTO-based request and response contracts
* Relational domain modelling with JPA and Hibernate
* PostgreSQL persistence and repository abstractions
* Request validation and centralized exception handling
* Internationalized application messages
* Soft deletion for protected historical records
* User-linked supplements and routines
* React and TypeScript frontend integration

### Current Development Direction

* Strengthening ownership controls between authenticated users and protected resources
* Expanding automated unit and integration testing
* Refining routine and supplement relationships
* Externalizing environment-specific configuration
* Preparing the application for a cleaner deployment workflow

## How I Approach Development

<div align="center">

`Understand` → `Model` → `Secure` → `Implement` → `Validate` → `Improve`

</div>

<br/>

I begin by understanding the user need and business rule behind a feature. I then model the domain, define boundaries between layers and secure access to the underlying data.

My goal is not only to make a feature work, but to make its behaviour understandable, testable and maintainable for the next developer who works on it.
